# Meme Signal Lab：从社媒发现到交易判断

## 项目定位

Meme 用户看到一个币时，通常同时面对帖子增长、KOL/返佣推广、活动任务、钱包标签与价格波动。真正需要回答的不是单一的“热不热”，而是：

1. 为什么现在被看见？
2. 谁在传播，主要在说什么？
3. 社媒变化是否与价格、成交和链上风险相互印证？
4. 用户看到时处于发射、扩散、高位换手还是存量交易阶段？

交易工具已有发现、行情、钱包分析与交易能力。本项目增加一个可解释研究层，把社媒、市场、生命周期和风险证据组织成连续决策故事。

## 数据产品流程

```text
X API / GeckoTerminal / 人工核验来源
                ↓
Go：查询、分页、重试、预算上限、Raw JSON
                ↓
Python：Schema、UTC、去重、实体消歧、文本分类
                ↓
阶段回放、社媒—市场对齐、风险证据边界
                ↓
Streamlit 连续研究页
```

这里的 Schema 可以理解为学校统一报名表：每条记录都必须按相同规则填写时间、作者、正文、互动、来源和实体，避免不同来源把同一列当成不同含义。

## 案例一：AX1 当前快照

X API 有界采集得到 499 条唯一帖子和 369 名独立作者。页面先展示社区当前主要话题、表达倾向与参与者类型，再把社媒频次与价格、成交变化按北京时间对齐。

AX1 的价值不在于得到一个“热度分”，而在于区分：

- 自然原创、引用扩散、普通回复和任务互动；
- 头部内容带动与更广泛作者参与；
- 发射阶段市场活跃与后续价格回撤；
- 社媒证据已经存在，但持仓、DEV、权限、LP 与退出容量仍需验证。

因此结论是“传播与市场活跃同时存在，风险证据尚不完整”，而不是“热度高所以应该买”。

## 案例二：NIULAI 完整生命周期

NIULAI 从 8 月开始发酵，不能只用最近几天的帖子代表全程。项目采用历史分窗与近七日连续窗口两种口径，经实体消歧后保留 544 条、387 名作者，并排除 311 条同名币、错误 CA 或含义模糊内容。

复盘得到的链路为：

1. Web2 猎奇内容引起围观；
2. 社区把人物/梗翻译成 Ticker 与合约地址；
3. KOL、早期收益和价格截图提供社会证明；
4. 价格与盈利内容反向扩大传播；
5. 交易所入口降低参与门槛；
6. 讨论转为回撤、持仓、抄底与交易所预期。

近七日连续样本有 180 条，其中 20.6% 为自动钱包播报。这说明当前仍有存量关注，但它与首次自然爆发不是同一种热度。

## 专业性体现

### 不把帖子数当作全部结论

项目同时观察作者覆盖、原创/回复结构、相似文本、低信息内容、话题、表达倾向、传播角色与生命周期。单个指标只回答一个局部问题，不被包装成万能分数。

### 不把时间相关写成价格因果

社媒和 OHLCV 按统一时区与粒度对齐，用于观察共同变化。没有实验或更强识别设计时，只描述时间关系，不声称某条帖子造成涨跌。

### 不让同名币污染案例

NIULAI 通过 Ticker、CA、链、项目语境和排除词进行实体消歧。被排除记录保留原因，便于审计，而不是静默删除。

### 缺失与冲突也是结果

持仓集中度、DEV、聪明钱成本、权限、LP、滑点和退出容量没有可靠证据时显示“待验证”。项目声明、二级来源与已验证事实分层保存；冲突不会被选择性覆盖。

## 用户与平台价值

对用户：更快区分真实扩散、任务噪声、自动播报与已经错过的阶段，并在交易前看到关键风险缺口。

对平台：把社媒发现与现有行情、钱包、合约和交易能力连接起来，提高信号解释力、风险提示质量与长期留存，而不是只优化点击或短期成交。

## 工程实现

- **Go 采集器**：X API 查询、分页、超时重试、时间窗口与预算上限。
- **Python 管道**：Schema 验证、UTC 统一、去重、实体消歧与可解释文本分类。
- **时间对齐**：社媒事件与小时 OHLCV 使用相同时间轴，明确区分相关与因果。
- **证据管理**：项目声明、二级来源、规则推断与已验证事实分层保存。
- **扩展设计**：Kafka/Flink 方案覆盖事件流、窗口聚合、迟到数据与时态 Join；当前版本不声称已部署生产集群。
- **自动验证**：Python 与 Go 测试覆盖采集、转换、去重、时间处理和核心聚合逻辑。

## 边界

- 不自动爬取受限制的产品页面；只使用人工核验快照或允许的官方接口。
- X 使用官方 API、有界查询和预算记录；样本不冒充全网数据。
- 不连接资金、不下单、不构成投资建议。
- 32 项 Python 测试和 Go 测试覆盖核心处理逻辑；Kafka/Flink 为升级设计而非已部署生产系统。
